Serve the SysIDE capability from a persistent Python worker instead of a per-request `syside check` CLI invocation: the bundled `syside` plugin now spawns one `python3` worker that imports the `syside` package once and keeps a single loaded model, so checks no longer pay the interpreter startup cost. The model is loaded lazily on the first capability request for a workspace, replaced when the selected workspace or its SysML sources change (watched and re-compared on every request), and never kept warm for more than one workspace at a time; workspaces without SysML files return empty results without starting Python. Add `survey`, `list-elements`, and `element-details` backend operations alongside `check`: `survey` reports per-package element counts, `list-elements` filters elements by element type, owning package, and name search, and `element-details` resolves full element detail by qualified name, with validated result shapes shared through the browser contract. SysIDE now requires Python 3 with the `syside` package installed on the machine running the session daemon, and because the plugin is owned by the session daemon, restart it after updating (`systemctl --user restart pi-web-sessiond`) and reload the browser.
